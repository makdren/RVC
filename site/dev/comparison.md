# Сравнение с INCY и Happ

Замеры на одном телефоне (vivo PD2536, Android 16, Wi-Fi), одна подписка Remnawave, локация «Автовыбор» (XRAY_JSON), 26.10.2026.

| | RVC 1.0.3 | INCY 3.7.9 | Happ 4.8.0 |
| :-- | --: | --: | --: |
| Размер APK (arm64) | **16,4 МБ** | 26,1 МБ | 64,6 МБ |
| Холодный запуск (среднее из 3) | **211 мс** | 694 мс | 354 мс |
| Память с подключённым VPN (PSS) | **98 МБ** | 136 МБ | 222 МБ |
| Процессы / потоки | 1 / **67** | 1 / 102 | 3 / 184 |
| Кадров за 10 с на главном экране при подключении | **38** | 917 | 918 |
| CPU на 100 МБ трафика (тест скорости Cloudflare) | 3,2 с | 2,7 с | **2,6 с** |
| CPU в фоне, простой (медиана из 3 по 60 с) | 2,3 % ядра | 1,9 % ядра | **1,2 % ядра** |

Скорость через туннель у всех одинаковая (около 80 Мбит/с на загрузку): упирается в сервер.

**Что это значит.** RVC самый лёгкий по размеру, памяти и запуску, а интерфейс не крутит анимацию постоянно: у INCY и Happ главный экран перерисовывается ~90 раз в секунду, пока открыт. Зато на самом трафике RVC пока тратит на ~20 % больше процессора: INCY и Happ передают пакеты через hev-socks5-tunnel, а RVC — через TUN-вход Xray (gVisor), который выбран ради отсутствия локальных портов. Проверено: MTU (1500 против 8500) и частота сборки мусора Go на это не влияют — разница в самом стеке TUN.

Как мерили: CPU — сумма `utime+stime` всех процессов приложения из `/proc/<pid>/stat`; память — `dumpsys meminfo`; кадры — `dumpsys gfxinfo`; запуск — `am start -W`. Простой в фоне зашумлён трафиком других приложений; Happ на этом телефоне настроен пропускать через VPN не все приложения, поэтому его фоновый трафик меньше.
